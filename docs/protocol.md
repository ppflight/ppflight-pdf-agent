# ADMIN ↔ PDF Agent protocol

The configured `admin_url` is the PPFlight HTTPS API base, by default
`https://www.ppflight.com/api/pdf-agent/v1`. The agent appends the paths below,
for example `POST /api/pdf-agent/v1/agents/claim`. It only polls this API over
outbound HTTPS. It never reads a Laravel database, a mutable settings endpoint,
or a local copy of main-site settings.

Every request and response is JSON. ADMIN may wrap a response object as
`{"data": {...}}`; the agent accepts either that envelope or the object itself.
No binding code, bearer token, download HMAC key, grant, or artifact path may be
logged.

## Global singleton admission

ADMIN permits **one active PDF Agent globally**. This is a database invariant:
the active-binding record has a unique active `binding_slot = "primary"`
constraint (or transactional equivalent). It is not enforced by local state.
Another bind must return `409 Conflict` with
`{"code":"pdf_agent_already_bound"}`; it must not displace the active agent.

The worker itself advertises and enforces a single render/polling loop
(`concurrency: 1`, `max_jobs: 1`). ADMIN's database constraint remains the
authority across hosts and restarts.

## ADMIN settings and immutable snapshots

The future ADMIN navigation is **System settings → PDF Agent**. It owns the
editable seller company name, address, support/footer email, Agent API base URL,
and public-download base URL. It shows the unique agent binding, version,
heartbeat, and task state, and provides controls to generate a one-time binding
code, test connection, disable, or rotate credentials.

At task creation ADMIN freezes all render-relevant settings in the task's
`snapshot`; the Agent renders only that snapshot and verifies its canonical
SHA-256. In particular, the snapshot contains the renderer's `issuer` object
with `company_name`, `address`, `support_email`, and `footer_email`. A later
settings change affects only later tasks.

## Bind

`POST /agents/bind` has no bearer token. The CLI supplies `binding_code` only
through stdin (or a root-owned private file), never a URL or command argument.

```json
{
  "binding_code": "one-time-secret",
  "identity": {"hostname": "edge-pdf-01"},
  "capabilities": {
    "binding_mode": "singleton",
    "concurrency": 1,
    "task_types": ["render", "invalidate"]
  },
  "protocol_version": 1
}
```

Successful response is `200` or `201` and contains exactly:

```json
{
  "agent_id": "agent-01",
  "agent_uuid": "7c6c4fd8-46e7-4d0f-82e5-dbe07f03be41",
  "agent_token": "opaque-bearer-token",
  "download_hmac_key": "base64url-key",
  "binding_slot": "primary",
  "singleton": true
}
```

The response is stored in `/var/lib/ppflight-pdf-agent/state.json`, mode `0600`
and owned by `ppflight-pdf`. Local state is changed only after ADMIN accepts the
bind. `409` with `pdf_agent_already_bound` leaves the existing local state
unchanged.

## Heartbeat and claim

All subsequent calls use `Authorization: Bearer <agent_token>`.

`POST /agents/heartbeat`:

```json
{
  "agent_id": "agent-01",
  "version": "1.0.4",
  "binding_mode": "singleton",
  "capacity": 1,
  "running_jobs": 0,
  "summary": {"artifacts_ready": 3, "tasks_succeeded": 8}
}
```

ADMIN returns `{ "ok": true }` when the binding is accepted. The agent sends a
heartbeat before polling and at its configured interval. An explicit `401`
clears the local binding state and stops the worker and local download listener;
an operator must bind again. A `403` can be generated by a public WAF and is
therefore retried without deleting local credentials. `409` means the global
binding is no longer valid, so the worker likewise stops instead of continuing
as a stale Agent.

`POST /agents/claim`:

```json
{"agent_id": "agent-01", "max_jobs": 1}
```

The response is exactly `{ "task": null }` or `{ "task": TASK }`. A render
task is immutable and has exactly these fields:

```json
{
  "id": "task-01",
  "type": "render",
  "artifact_id": "invoice-100",
  "revision": 4,
  "download_filename": "PPFlight-invoice-100.pdf",
  "snapshot": {"schema_version": 1},
  "snapshot_sha256": "canonical-json-sha256"
}
```

An invalidate task contains only `id`, `type`, `artifact_id`, and `revision`.
The agent refuses unknown fields, altered snapshots, invalid filenames, and more
than one claim at a time. The abbreviated snapshot above illustrates transport
only; a renderable snapshot must satisfy the renderer's complete invoice schema.

## Complete and public download grants

After processing, the agent calls `POST /agents/complete` with its bearer token:

```json
{
  "agent_id": "agent-01",
  "task_id": "task-01",
  "result": {
    "status": "ready",
    "artifact_id": "invoice-100",
    "revision": 4,
    "sha256": "pdf-sha256",
    "size": 234567
  }
}
```

Completion is durable and retry-safe for the same task and canonical task
fingerprint. A rendering error reports `{"status":"failed","code":"processing_failed"}`
without internal details. Locally, the Agent emits only a fixed allow-listed
diagnostic code to stderr (and therefore journald); it never logs a task,
snapshot, renderer output, exception text, credential, path, or signed URL.
ADMIN must return exactly `{"ok":true}` (or that
object inside the documented `data` envelope); otherwise the completion stays
pending locally and is retried before another task is claimed.

The local download server accepts only:

```text
GET /v1/download/<artifact_id>?grant=<signed-token>
```

The short-lived grant has `aud`, `artifact`, `revision`, `exp`, and
`agent_uuid` claims. It is HMAC-signed using the binding response key, expires
within five minutes, and must match the bound `agent_uuid`. The public URL may
use `https://pdf-worker.ppflight.com` through Tunnel/Nginx, but grants must not
be logged or exposed by a static artifact directory.

Grant construction is byte-exact:

1. Serialize the five-claim object as UTF-8 JSON with keys sorted, no
   insignificant whitespace, no escaped non-ASCII characters, and no NaN.
2. Base64url-encode those bytes without `=` padding; call this segment `P`.
3. Decode `download_hmac_key` from unpadded base64url and calculate
   `HMAC-SHA256(key, ASCII(P))`.
4. Base64url-encode the MAC without padding and emit `P.MAC`.

The public reverse proxy permits only `/v1/download/...`; `/healthz` remains a
loopback-only liveness check.
